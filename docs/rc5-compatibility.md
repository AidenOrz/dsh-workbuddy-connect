# DSH 0.2.1-rc.5 兼容修订

此修订精确支持 DSH `0.2.1-rc.5`，插件运行依赖和开发依赖中的 pi-ai 均为 `1.4.0`。
`engines.dsh`、DSH service peers 和开发依赖保持一致。旧内核及未来 rc 版本未包含在支持范围中；升级前应核对宿主版本，旧内核保留历史修订版。
保留现有 `0.7.15` 包版本，由维护者决定下一次发布版本。

## 修改原因

- rc.5 的 layout 包已声明 `shell.overlay`，插件的旧镜像声明带有不同 owner 类型，会触发声明合并错误。改用宿主的仅类型导入，不引入浏览器运行时依赖。
- 探测控件仅订阅、读取 ModelDirectory store，props 收窄为 `getSnapshot` 和 `subscribe`；测试替身使用 `satisfies`，补齐 `pending` 等状态字段，保留 null/undefined 与会话切换回归场景。
- rc.5 使用 pi-ai 1.4.0，旧 1.3.0 的唯一符号和类私有成员类型不能与宿主互认。依赖及运行时版本守卫同步升级，不通过忽略类型检查掩盖冲突。
- 跨实例测试继续物理复制第二份 pi-ai，但按该包声明的 dependencies 链接依赖，包含 scoped packages，避免新增遥测依赖后夹具失效。

两个缓存写入失败用例改用普通文件作为父路径，以 ENOTDIR 确定触发失败；不再依赖平台特有的 `/proc`，避免 Linux/Node 24 的递归 mkdir 卡住，也让 Windows 能验证相同的容错行为。

## 验证方式

```sh
pnpm run typecheck
pnpm run build
pnpm test
git diff --check
```

2026-11-02 最终回归：60 个测试文件，902 项通过，0 项失败，7 项跳过；前后端 TypeScript 检查及构建均通过。

需先构建再检查依赖构建产物的版本测试。`lib/` 为受版本控制的分发产物，必须与源码一起更新。
测试使用模拟上游；一次 Linux Web 真实 `glm-5.3-flash` 请求已确认能够完成。
这不代表所有模型、Windows/macOS Desktop 或全部 UI 操作均已验证。

## 上下文长度与本修订的关系

如果上游返回“内容过长，请精简或新建任务”，应另行核对工具定义、历史消息、输出预留与所选模型的上下文限制。
工具定义本身会占用上下文，短用户输入不保证整体请求短。本修订解决 rc.5 类型和依赖兼容，不改变模型上下文窗口，也不移除用户的 MCP 工具。
